# 当前项目状态

更新：2026-10-03。本文是当前范围和验证状态的统一入口；旧开发路线和历次审查见[历史归档](../archive/README.md)。

## 当前交付范围

项目仅管理 **Mihomo**。Rust 业务层提供配置、订阅、模板、事务、激活、运行设置和服务操作，CLI、TUI 与本地管理 Web 共用这些流程。

Web 由 **ClashTui 本地管理页 + 固定 MetaCubeXD v1.273.1 核心面板**组成。前者管理本地文件和服务，后者连接 Mihomo API。当前使用上游固定发布包，未维护 MetaCubeXD 源码分支。

基线来源与当时的协议分析见[固定版本审计](../archive/metacubexd_v1.273.1_audit_zh.md)。功能入口逐项见[三端矩阵](cli_tui_web_parity_zh.md)，共享逻辑见[功能设计](../development/clashtui_feature_design_zh.md)。上游 agent 的 WebDAV、script/merge、桌面壳和任意数量端点档案不在当前范围内。

## 本阶段开发成果

- CLI、TUI 和本地 Web 共用管理业务流程，补齐配置、订阅、模板、运行设置、Provider、连接、日志、服务与维护入口，具体差异以三端矩阵为准。
- Web 使用本地管理页配合固定上游 MetaCubeXD 发布包；加入独立认证、后台任务记录、冲突检查及跨端回读。
- 移除 sing-box 支持、核心切换、模板、资源和安装下载，保留旧数据库迁移与原始数据备份。
- 修复多轮审查与实机测试发现的业务、交互、权限、失败恢复及安装卸载问题。
- 建立模拟、无头浏览器、PTY、真实 VM 和联网专项自动入口；文档归并为使用、开发、参考、测试与历史归档。

这些是已实现的开发成果；验收结论与未完成范围分别记录如下，不能将功能入口存在等同于所有环境均已验证。

## 尚不能宣称完成的验收

- 真实浏览器/终端体验 H01–H06；超过已验证 100 个新增 Profile、600 秒持续运行的规模/长时专项。
- 公网 UDP 的有效转发与失败原因；其他 Mihomo 版本完整回归（v1.19.32 目前只验证升级、重启与状态回读）。
- 发布资产全新下载安装，以及其他 Linux init 系统或发行版安装。
- macOS/Windows 原生安装、服务、系统代理与剪贴板；Mac 远程操作 Linux VM 不计作 macOS 原生验收。
- 远端三平台 CI 的实际结果。

三端业务入口已覆盖主要范围，但仍有交互和核心能力边界：TUI Profile 默认 U 批量更新已补齐；Mihomo 1.19.24 未暴露规则 disabled 状态，本次规则开关验收跳过。文件外部编辑器也不具备 Web/CLI 修订保存的同等并发保障。

因此当前优先推进 mini PC 自动闭环，并按需开展六项人工体验检查；尚不能将目标表述为“所有功能、平台和交互均已验证完备”。

## 接下来怎么测

1. 按[mini PC 自动闭环方案](../testing/README.md)在本机执行 A 隔离回归、B 真实 VM，并取证、恢复和核对宿主网络。

3. 只有人工体验 H01–H06 按需接入 Mac，填写[简化记录](../testing/manual_test_record_zh.md)，不再要求手工重跑 M01–M30。
4. macOS/Windows 原生测试放到相应平台，以自动化为主；新执行报告放入 `docs/testing/reports/`。

C 层已实际开发并执行，人工步骤和独立专项边界见方案；VM 启停、推送与恢复见[VM 操作](../testing/local_vm_testing_zh.md)。

统一入口 `bash scripts/acceptance.sh` 的覆盖与判定见[覆盖契约](../testing/acceptance_coverage_zh.md)。新修复包括系统服务新建文件的组权限、Provider 测速使用核心健康 URL、终端编辑器接管与短命编辑器恢复通知竞态、节点筛选后的目标索引、Web 轮询重建按钮与前台操作竞态、Provider 类型切换被旧延迟轮询阻塞；当前构建的验证以总入口最新报告为准。
