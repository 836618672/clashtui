# 2026-10-02 缺陷修复与验收

本轮修复此前实机测试发现的五项缺陷。完整隔离流水线通过；真实 Linux VM 通过 32 组测试，0 项失败、0 项已知失败、1 项核心能力跳过。此结果覆盖当前 Linux/Mihomo 1.19.24 环境，不代表其他平台或所有核心版本已验收。

## 五项修复

| 缺陷 | 最终行为 | 回归证据 |
|---|---|---|
| Provider 路径越界 | 缓存读写统一限制在核心目录；拒绝 `..`、绝对路径、目标或祖先符号链接。生成/激活前也检查无 URL 的文件 Provider 和合并后的配置 | Rust 路径测试；VM 相对越界、绝对路径、目录符号链接的更新/激活均拒绝，外部文件保持原值 |
| text/MRS 被当作 YAML | 提取并保留 format/behavior；YAML 检查对应序列，text 检查 UTF-8，MRS 使用 Mihomo `convert-ruleset` 实际解码后才替换缓存 | VM 用核心生成真实 MRS，text/MRS 下载和激活均通过；损坏 MRS 拒绝且旧缓存不变 |
| 下载失败有缓存误报成功 | 模板与普通 Profile 使用共同下载结果；旧缓存保留，本次资源 `ok=false` 并保留错误，CLI 非零、Web 展示部分失败、TUI 单次/批量提示失败 | VM HTTP 503、CLI 输出/退出码、Web 结果和旧缓存字节验证 |
| 显式空分组恢复旧分组 | 仅字段缺失时兼容旧文件；显式 `{}` 表示清空，旧数据库迁移也尊重已存在字段 | 进程回归；VM Web 保存、CLI 读取及模板生成均保留空分组 |
| 只读 CLI 改变修订号 | 移除 CLI/TUI 退出时无条件保存；数据库使用 BTreeMap，显式保存时相同字节不写文件；业务变更由原事务提交 | 进程连续读取测试；VM Web 取状态→10 轮 CLI status/state/read→使用原修订执行 Web 校验；TUI 导航/运行模式修改/退出保持数据库字节 |

`no_pp` 内联代理订阅；规则 Provider 保留原来的 `RULE-SET` 引用、目标策略和匹配行为，使用核心支持的 yaml/text/mrs 格式，避免此前直接追加规则造成语义变化。VM 在 `no_pp` 开关开启后再次激活 text/MRS，并检查生成配置保留规则引用。

路径防护默认不接受额外 SAFE_PATHS。核心根目录可以是用户配置的目录；其下 Provider 路径不接受符号链接。防护覆盖正常协作的配置写入，不宣称能抵抗另一个恶意本地进程并发替换目录的文件系统竞态。
