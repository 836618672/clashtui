## 2. mini PC 当前可执行的主流程

所有命令在 `/home/yulinye/clashtui` 执行。使用已有 Rust 1.89+、rustfmt、clippy、Node.js 22+、Python、Playwright 与 Chromium 环境；工具不在当前 shell 时进入项目已有的 Nix 工具环境。依赖准备方法见[流水线](test_pipeline_zh.md)。浏览器下载只属于测试工具准备，不需要图形界面。

### 2.1 单一入口

先确认无其他测试或 Mac 会话正在使用可丢弃 VM。入口会先归档客机旧证据，再重置测试磁盘；宿主的网络和服务仅做只读对照。

```bash
cd /home/yulinye/clashtui
bash scripts/acceptance.sh
```

依赖不在 PATH 时自动进入 Nix 工具环境。需要已准备好的 VM 基线、已生成的 Vue 前端和缓存依赖。自动顺序是：宿主对照→旧证据归档→A→安装器→本轮构建→B/C→失败现场归档→恢复 VM→宿主对照。普通失败仍保留其他阶段的结果。SIGINT/SIGTERM 会终止当前阶段并执行恢复；宿主断电、SIGKILL 无法运行清理，重新执行前按[详细指南](tui_web_testing_zh.md)第 11 节人工恢复。

结果在 `target/acceptance/<时间>/report.json`。终端出现 `automatic_passed=True` 且退出码 0 才表示固定 Linux 范围自动通过。缺少 C 用例、阶段失败、恢复失败、报告缺失或宿主对照变化均为失败。截图、trace、PTY、日志及客机归档集中在该目录；分享前脱敏。

### 2.2 规模和持续运行

```bash
bash scripts/acceptance.sh --soak-seconds 600
```

默认 100 个 Profile、24 次并行读取、120 秒持续运行；参数可调为更长时长。它验证指定负载下的响应、内存和只读修订稳定性，不证明任意规模或无限时间稳定。

### 2.3 人工结果与范围验收

自动通过后完成 H01–H06。按照[记录模板](manual_test_record_zh.md)保存与同一二进制匹配的 JSON，再执行：

```bash
bash scripts/acceptance.sh --manual-record /tmp/clashtui-human-record.json
```

`accepted_current_scope=True` 表示指定 Linux 客机、核心和面板的自动加人工验收通过。公网目标、其他核心版本及 macOS/Windows 原生平台有独立证据边界，不能由该字段推导已验收。自动报告不会代填人工 PASS。

单独排障可运行 `node scripts/test-pipeline.mjs --browser` 和 `bash scripts/vm-test.sh`；后者不会执行总入口的最终恢复包装，正式验收应使用 `acceptance.sh`。

### 2.4 公网、安装与升级的扩展闭环

`acceptance.sh` 保持受控回环网络。需要把当前 mini PC 可执行的联网和安装专项一起跑完时，使用：

```bash
bash scripts/full-auto.sh --subscription-file /home/yulinye/.config/clashtui/profiles/9yun --soak-seconds 600
```

订阅文件须为单行 HTTPS URL。该路径是本机当前实际使用的订阅来源；不要把地址或凭据复制到文档、命令行参数和共享日志中。入口只读取宿主文件，通过 SSH 标准输入传给客机；每轮测试结束后重置客机。

扩展用例：P01–P08 验证真实订阅、CLI/Web 更新与额度、全部节点测速、选定节点 HTTPS、拒绝后恢复、公网 DoH、TUN TCP/UDP 及停用清理；两个安装轮次各 L01–L05 分别验证真实用户/系统安装、启动、正常关机后重新启动的自启、取消卸载和运行中卸载；U01–U07 验证内置面板离线可用、Geo 与核心真实更新、下载失败文件保留及核心回退。随后执行完整 A/B/C 和指定时长的持续运行。节点测速失败单独计数；“公网用例通过”不表示订阅中的每个节点都可用。

汇总结果为 `target/full-auto/<时间>/report.json`。只有五个范围均通过、报告齐全、构建摘要一致，才得到 `automatic_available_scopes_passed=true`。各专项报告位于 `target/extended-acceptance/<时间>/`，均核对宿主路由、策略规则、DNS 和 Mihomo 服务，以及被测业务源码的前后一致性。测试凭据会进入客机临时配置，因此不要另行分享客机原始配置或磁盘。

UDP 探测优先使用公共 STUN 的 UDP/3478，并以 UDP/53 DNS 作为备用；要求真实响应与核心远程节点连接链同时成立。具体成功协议见 P08 的 `udp_probe`，不能据此推导任意 UDP 端口或目标可达。多个节点的有界重试不会把未取得响应的节点算成可用。

单独重跑：

```bash
bash scripts/extended-acceptance.sh --suite public --subscription-file /home/yulinye/.config/clashtui/profiles/9yun
bash scripts/extended-acceptance.sh --suite lifecycle
bash scripts/extended-acceptance.sh --suite system-lifecycle
bash scripts/extended-acceptance.sh --suite upgrades --subscription-file /home/yulinye/.config/clashtui/profiles/9yun
```

安装轮次使用当前构建与已准备的核心，实际执行安装器、systemd、重启和卸载；它不代替发布资产的全新下载安装。联网更新轮次使用真实上游下载，记录实际升级版本。升级后的状态回读不等于所有其他核心版本的完整 A/B/C 回归。macOS/Windows、其他 init 系统和超过本轮规模/时长的范围仍需独立证据，不能由汇总字段推导通过。SIGINT/SIGTERM 会中止当前范围并执行其恢复；SIGKILL 或宿主断电时按第 2.1 节的恢复说明处理。

## 4. 自动化补齐顺序与交付标准

| 优先级 | 自动用例或独立专项 | 交付标准 |
|---|---|---|
| P0 | 单一总入口：A→B→证据归档→最终恢复；失败也收集日志与宿主对照 | 构建摘要一致，失败非零，恢复失败也计失败；中断/未执行单独列出，不静默 reset 现场 |
| P0 | M08/M09/M22/M28：订阅错误矩阵、代理选项/批次、任务中断、停服迁移 | CLI 退出码、Web job、PTY 文本、文件摘要、真实核心回读相互核对 |
| P1 | M02/M07/M10/M14/M17/M18/M20/M23 的真实页面/PTY 操作 | 使用真实键盘/鼠标输入；常规路径不以 DOM 强制 click 掩盖焦点或忙碌问题；失败截图/终端记录 |
| P1 | M30 规模和长时测试，TUN 权限/停止清理 | 固定数据量/时长/资源阈值，前后状态断言；报告资源条件，不泛称无限规模稳定 |
| P2 | M26/M27 公网、版本和升级；Linux 原生安装生命周期 | 测试目标及版本固定，快照恢复；不得替换宿主二进制或改宿主网络 |
| 独立平台 | macOS/Windows 构建、安装、服务、剪贴板与系统代理 | 在相应系统执行并恢复；平台自动化缺失不能拿 Linux 结果代替 |

P0/P1 已纳入统一入口；是否通过需查看本轮逐项结果。P2 公网/升级已通过独立 VM 入口执行，其中公网 UDP 仍失败；其他原生平台仍须独立环境，不能用离线夹具代替。详细断言映射见[覆盖契约](acceptance_coverage_zh.md)。

## 5. 必须人工判断的短清单

自动层成功并恢复基线后再接入 Mac。准备只用[详细指南](tui_web_testing_zh.md)第 2 节的 VM 推送/权限/隧道步骤和第 3 节 Mac 连接；H01–H06 不需要逐项执行 M01–M30。自动回归会清空测试订阅，先在 mini PC 执行 `bash scripts/prepare-human.sh`：自动准备不激活的 `c-human-clipboard` 回环订阅供 H06 使用，随后停止 HTTP 夹具；无需手工常驻订阅/DNS/流量服务。准备令牌参考第 2.2 节，结束按第 11 节恢复。

Vue 核心面板与本地管理统一在 `http://127.0.0.1:39091/`，只填写管理令牌；不再配置 MetaCubeXD 端点或 secret。Mac 不设置系统代理、DNS 或 TUN。

预计操作 15～30 分钟，不含 SSH 准备、故障排查或另一个浏览器专项。每项只做一个代表路径，失败才按原 M 用例展开。

| 编号 | 人实际操作 | 观察与通过条件 |
|---|---|---|
| H01 显示 | Chrome 打开统一 Vue 面板 39091；浏览器宽度约 1440、1024、768 | 表格、按钮、弹窗和结果可读，无互相遮挡；窄屏可滚动并恢复；记录实际尺寸 |

| H03 错误提示 | 错误令牌连接一次，再正确连接；尝试删除当前 baseline Profile | 认证与删除保护提示明确，未发生删除，错误后可以继续操作；不要为制造错误改真实凭据 |
| H04 终端 | Mac Terminal 两层 SSH -tt 启动客机 TUI，切换九页、帮助；140×40、100×30、80×24，最后 q | 字符和高亮可辨，缩放后可恢复，输入响应正常，退出后 shell 回显/光标正常 |

H05 可以先按 M23 配置终端编辑器再执行；这是 Linux 客机编辑器体验，不是 macOS 原生编辑器。浏览器平台适配不能仅凭 Linux Chromium 结果判断，因此支持 Safari 时应安排对应人工观察或 Mac 自动浏览器测试。

结果填[简化记录模板](manual_test_record_zh.md)。功能性断言仍归 mini PC 自动报告；H 项只补充人判断的体验证据。

## 6. 如何给出验收结论

分别汇总 A/B/C 的新报告、D 专项、H 人工体验和原生平台结果。只在相应范围通过后声称该范围闭环。

例：“本轮 Linux/Mihomo 1.19.24 自动回归通过，恢复与宿主网络核对通过；C 指定用例全部通过；Mac H01–H06 已执行四项、两项未执行；公网与 macOS 原生服务未测。”

FAIL 必须对应错误、构建、触发步骤、日志及恢复结果；核心不支持为 SKIP；缺少凭据/依赖为 BLOCKED；未实现或未执行为待补/未执行，均不得算 PASS。没有显示器不会阻止 A–D，缺少 Mac 不应阻断这些层的开发和验证。
